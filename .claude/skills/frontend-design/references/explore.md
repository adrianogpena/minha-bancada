# Explore mode

Scope: ideas and alternatives for the UI (new theme, button placement, revamp, different data presentation). Writes nothing until the user picks a direction.

## Procedure

1. Read the rules (generic and the project's `frontend-design.md`) as a baseline, not as constraints. Done when the rules a direction could change are known.
2. Propose 2-3 directions. Each gives: an ASCII wireframe, the rules it changes, the migration cost (screens and components touched), and any project check it conflicts with (for example the raw-button guard). Done when every direction has all four parts.
3. Stop and ask the user to pick one. Write no code and no rule before the pick.
4. After the pick, hand over to Guard (Modes in `SKILL.md`) with the rule changes pre-approved: the amend is written to the project's `frontend-design.md`. If the project file defines its own revamp mode, follow that after the pick. Done when the picked direction runs through Guard.
